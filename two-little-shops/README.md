# 菲菲和屯屯 · 点餐初版

## GitHub 点餐站（第 9 版）

`https://noground.github.io/?look=cute` 支持选择或新建昵称、多份下单、留言、订单记录、再来一单、确认吃好与评价。菜单、页面文字和上传配图读取原站，两个网址共用 D1 数据；各地址需各选一次昵称，同名昵称读取同一组订单。

GitHub 通过仅允许 `https://noground.github.io` 的 `/api/github` 访客接口连接原后台。不转发平台身份或店主 Cookie，不支持管理操作。普通昵称会话只在 HTTPS 请求体中传输，不放入网址，也不依赖跨站 Cookie；原站店主登录和独立管理页保持不变。

运行 `node scripts/build-github-pages.mjs` 生成 `work/github-pages-live/dist`，发布到 GitHub 的 `gh-pages` 分支。网络不能连接原后台时，页面明确提示，不能离线提交订单；国内网络质量仍需实际验证。

检查：`node --experimental-strip-types tests/github-bridge.mjs`、`node --experimental-strip-types tests/github-client.mjs`、`node tests/github-orders.mjs`。最后一个检查只使用本地数据库，验收后清理新建昵称和订单。

## 图片与文字管理（第 8 版）

管理页单独使用 `/manage?look=cute`，点餐网站不显示管理入口。旧的 `?space=manage` 收藏链接会跳转到新地址。使用创建网站的 ChatGPT 账号进行店主登录；店主不必先选昵称就可以管理。普通点餐人继续只选昵称，不能修改页面内容。

「图片与文字」分为首页与名称、饮品店、小厨房、观影角、剧集收藏、背景与动画。可以上传 JPG/PNG/WebP、粘贴 HTTPS 配图网址、修改标题和介绍；剧集支持新增、移出、排序、独立配图，以及收藏点位置和取景设置。首页入口图留空时沿用空间主图。原图支持 15MB 以内。照片自动压缩为 JPEG；透明图片使用 WebP 或 PNG 保留透明通道，编码超出预算时继续缩小，兼容 Safari。

修改后可以「预览这一页」，草稿只作用于当前浏览器页面，返回管理后仍然保留。点「保存到网站」才会对大家生效；「本栏恢复默认」也只是先改草稿。离开未保存页面时浏览器会提醒。遇到其他页面已保存的冲突时，后台拒绝覆盖，需重新载入已保存内容后修改。

配置存放在 D1 `overrides` 的 `site-content` 记录中；上传配图以不可变的 `content-photo-*` 键单独保存，只有配置成功保存才会引用新图片。这些记录不会进入菜品菜单，账号、订单与评价保持原有结构，不需要数据库迁移。旧店铺封面会兼容载入。

本地检查：`npx tsc --noEmit`、`node tests/smoke.mjs`、`node tests/content.mjs`、`node --experimental-strip-types tests/photo-processing.mjs`。内容检查验证店主权限、匿名与昵称账号拒绝写入、图片持久化、剧集编辑、版本冲突与配置隔离，并恢复验收数据。`node tests/content.mjs --preview` 只在 loopback 启动一次性的本地验收登录，登录夹具 1 小时失效，不用于部署。

第 6 版加入同款小猫与卡皮巴拉：小猫守着饮品吧台，卡皮巴拉在厨房，两只依靠在观影角沙发上。四张场景与角色图由内置 imagegen 生成，提示词和素材映射见 [visual-assets-v6.md](docs/visual-assets-v6.md)。WebP 只压缩格式，送餐角色保留透明通道；背景新增咖啡、爪印与胶片线稿。

家庭观影角现有七部剧，新增《纸钞屋》。收藏画、字母彩灯、家庭相框、餐馆双杯与蛋糕、列车、红衣面具等陈设遍布房间。电脑可点击收藏点；所有尺寸都能通过剧集卡片切换放大的收藏细节与说明。图片为原创场景演绎，不是剧照。

订单 API 成功后播放约 6 秒的端餐盘小剧场，随后进入观影角并显示下单成功。实际制作状态仍由订单记录决定。动画可跳过，支持减少动态效果并在卸载时清理计时器。观影角的「看一遍送餐小剧场」按钮只预览动画，不创建订单。

一个适配手机和电脑的家庭小天地：菲菲饮品店、屯屯小厨房、家庭观影角。

- 首页双店入口、分类浏览和搜索；菜品图片、简介、独立配料列表。
- 口味选择、多份数量、跨店购物袋、订单留言和再来一单。
- 直接选择或新建昵称；无邮箱、密码或数字口令，设备会记住所选名字。
- D1 持久保存用户、订单、评价和菜单修改；购物袋暂存在当前浏览器。
- 订单：已下单 → 制作中 → 可以开饭啦 → 已完成；点餐人可以确认吃好并写星级与文字评价。
- 店主可新增/编辑菜品、上下架、更换两家店封面、上传照片、查看所有订单和处理状态。
- 示例价格只记录参考合计；没有支付、配送、短信或推送通知。订单页每 30 秒刷新，也可手动刷新。

## 开发

需要 Node 22.13+。此项目由 Sites Vinext starter 创建。

```sh
npm ci
npm run build
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_odd_roxanne_simpson.sql
npm run dev -- --port 5173
```

本地数据库与线上数据库相互独立。迁移只需在新的本地数据库执行一次；不要重复执行。

## 检查

```sh
npx tsc --noEmit
node tests/smoke.mjs
```

Smoke check 仅允许 localhost，会创建本地验收昵称、订单和一个旧版店主会话夹具，验证昵称切换、历史记录、普通名字不能获得管理权限，以及点单、评价和菜单编辑。不会向线上写入验收数据。

## 初版边界

昵称是共享点餐名字，不是安全账号：拿到链接的人可选择已有名字查看该名字的记录。访客不需要 ChatGPT 登录。Sites 访问模式设为公开链接，适合只向熟人分享。

普通昵称会话始终按访客权限处理，即使选择了旧版店主的同名昵称也不会获得管理权限。原有已验证的店主会话继续可用；网站所有者也可通过独立管理网址的 Sites 登录身份进入管理。所有者身份在服务端校验，不通过昵称授予。旧用户 ID 和订单保留，旧口令字段仅为兼容数据结构，不再用于普通点餐。

上传图片会在浏览器压缩并保存在 D1，每张约 180KB 以内；图片以 URL 复用，不复制进订单。适合小菜单，后续大量图片可迁移到 R2。菜品名称、价格、口味会作为订单快照保存，上传图片在历史订单中随菜单图片更新。

示例菜单和配图可直接在小店管理里替换。素材来源见 `CREDITS.md`。

## 家里的三个空间

首页有双店点餐入口和家庭观影角。饮品店使用米色橄榄配色；厨房使用格纹与暖陶色；观影角使用夜蓝色。两套原版/可爱外观继续保留。场景已升级为真实材质的原创生成图，剧集卡片展示房间中对应的收藏细节，无外部海报请求。

观影角为剧集氛围收藏，不提供视频播放。选择 POI、怪奇物语、超感猎杀、我们这一天、破产姐妹、雪国列车、纸钞屋可切换收藏细节与介绍；选择会保存在当前浏览器，可调暗阅读灯，并可跳转饮品店、小厨房或打开购物袋。`?space=feifei`、`?space=tuntun`、`?space=cinema` 支持刷新后留在对应空间，可与 `look=cute` 组合。没有新增数据库表，也不改变账号与订单数据。
